# 司机申诉接口

实现架构第九节的司机申诉、补充材料、撤回和管理员复核。沿用 PLATFORM_ADMIN / DRIVER 两种角色；原始识别数据不回流模型。

- 新库执行 `src/main/resources/db/schema.sql`。

申诉功能启用后，直接告警处理入口也查询申诉表，部署前必须完成升级。

## 申诉对象与状态

司机只可对记录中 `driver_id` 为本人的分心行为申诉，不以当前车辆绑定关系替代历史归属：

| targetType | targetId | 可受理范围 |
| --- | --- | --- |
| ALERT | 告警 ID | SMS_ALERT 或 BACKLOG，当前为 OPEN 或 CONFIRMED |
| RECOGNITION | 识别记录 ID | 已参与判定、非 OOD、类别 c1—c9，且未关联分心告警的普通记录 |

速度未知异常不是司机违规，不受理申诉；正常帧、低速未参与帧和 OOD 帧同样不受理。已关联分心告警的识别帧需使用告警 ID 申诉，避免同一事实重复复核。

申诉状态：

| 状态 | 含义 |
| --- | --- |
| PENDING | 已提交，等待管理员复核，可补充文字/文件或撤回 |
| WITHDRAWN | 司机主动撤回；原理由和材料保留，可针对同一目标重新提交新申诉 |
| CONFIRMED | 管理员维持记录，申诉未通过 |
| REVOKED | 管理员撤销记录，申诉通过 |

同一目标只允许一条待处理申诉；已有最终复核结果时不再重复受理。撤回和复核均只能从 PENDING 流转，不可重复处理。已撤销告警无需申诉。

## 接口

全部接口携带 `Authorization: Bearer <token>`。

| 方法 | 地址 | 权限/用途 |
| --- | --- | --- |
| POST | `/api/appeals` | 司机提交 |
| GET | `/api/appeals` | 管理员全部、司机本人，筛选和分页 |
| GET | `/api/appeals/{id}` | 详情 |
| GET | `/api/appeals/{id}/events` | 按事件 ID 升序读取完整历史 |
| POST | `/api/appeals/{id}/supplements` | 本人追加说明 |
| POST | `/api/appeals/{id}/withdraw` | 本人撤回待处理申诉，无需请求体 |
| POST | `/api/appeals/{id}/decision` | 管理员复核 |
| POST | `/api/appeals/{id}/materials` | 本人上传材料，multipart 字段 file |
| GET | `/api/appeals/{id}/materials` | 材料元数据和下载地址 |
| GET / HEAD | `/api/appeals/{id}/materials/{materialId}` | 按申诉归属鉴权下载文件/读取响应头 |

管理员不能代司机提交、补充或撤回；司机不能决定复核结果。所有详情、历史、材料和下载入口执行归属校验，他人记录与不存在记录统一返回 404。

提交示例：

```json
{ "targetType": "ALERT", "targetId": 123, "reason": "对关键帧认定有异议，请人工复核" }
```

理由必填，最长 1000 个字符，去除首尾空白；司机 ID、组织归属和操作时间由服务端取得，不接受客户端指定。

补充说明请求为 `{ "content": "补充说明内容" }`，必填、最长 1000 个字符；每次追加独立事件，不覆盖提交理由。

复核请求为 `{ "status": "REVOKED", "reason": "经核实属于误识别，撤销记录" }`。status 仅接受 CONFIRMED / REVOKED，原因必填、最长 500 个字符；保存管理员账号/姓名快照和北京时间。对已确认告警的复核允许 CONFIRMED→REVOKED，或 CONFIRMED→CONFIRMED 维持原决定，均追加历史。

列表使用现有 `Result<PageResult>`，可筛选 `status`、`targetType`、`targetId`、`driverId`，page 默认 1，pageSize 默认 10、最大 100；按创建时间、ID 倒序。司机传入 driverId 只能进一步缩小本人范围。超出最后一页返回空列表和真实 total。

## 材料

最多 10 份，每份最多 1 MiB，接受 JPEG、PNG、PDF 文件头；不依赖客户端声明的 MIME 类型或后缀。Servlet 自身上传限制也会生效。文件存入 `file.upload-dir/appeals/日期/UUID.后缀`，客户端仅看到材料元数据和鉴权下载接口，不暴露磁盘路径。

文件名去除路径与控制字符；下载使用 attachment、no-store 和 nosniff。前端需携带 Bearer token 获取文件。`/upload/appeals/**` 直接访问已关闭，同时拦截 Windows 大小写变体及指向私有目录的静态别名。读取检查规范化和真实路径，拒绝路径越界。已撤回或已处理申诉保留材料供历史查阅，不允许再补充。

材料只做格式文件头和大小校验，不解析正文或执行文件内容。材料数据和事件保存失败时回滚元数据，并清理本次写入文件。

## 并发与结果

所有变更按“先锁目标记录，再锁申诉”的统一顺序执行。重复提交、两个复核竞争、复核和撤回竞争时只允许一个结果提交，冲突返回 409。

目标告警有待复核申诉时，原 `POST /api/alerts/{id}/reviews` 返回 409，要求管理员通过申诉入口处理。申诉复核对告警状态、告警处理历史、申诉状态和事件实行同一事务，失败全部回滚；事件中的 alertReviewId 指向对应告警历史。

普通识别记录复核只在申诉及事件表中保存决定，不修改原始预测、参与标记或 JPEG；未来识别查询和评分应关联终态申诉，不能只按原始预测判断是否有效。司机撤回不改变告警状态；复核不改变短信状态、不重置判定累计、不补发短信。

评分模块尚未实现，本阶段没有执行 +5 / +1 回补；未来评分应依据撤销结果并按目标唯一计账，防止重复回补。

参数错误返回 400，未登录或失效 token 返回 401，角色不符返回 403，不存在/他人记录返回 404，状态冲突返回 409，材料超限返回 413，不支持的请求/响应类型分别返回 415/406。错误正文统一为 Result，服务器未预期错误为 500。

## 验证

```powershell
$env:DRIVER_FLEET_DB_TESTS = "true"
.\mvnw.cmd test
Remove-Item Env:\DRIVER_FLEET_DB_TESTS
```

`AppealIntegrationTest` 使用真实 MySQL、MyBatis 和 JWT，材料使用独立临时目录。覆盖两种申诉对象、资格与归属、补充/撤回/再提交、角色权限、状态筛选、材料上传下载与静态路径绕过、并发竞争，以及创建、复核、材料写入的故障回滚。无需真实模型、摄像头或短信通道。

本次验证：Java 21 下开启数据库集成测试，全量 139 项通过，0 失败、0 错误、0 跳过，其中新增申诉测试 30 项。结束后已核对测试车队/账号清理，事件及材料元数据不存在孤立记录。

审阅补测覆盖了下载请求只接受 PDF、PNG、JPEG 时的越权/材料不存在场景：错误响应仍是 404 + JSON Result。三种格式的越权用例修复前均无法生成正确响应，显式设置异常响应类型后全部通过。

另补两项带同步屏障的并发测试，强制制造旧事务快照：剩一个材料名额时两个上传只有一个成功，最终文件与元数据均为 10 份；申诉开始校验后刚提交的识别帧与告警，也不能绕过“已关联告警须对告警申诉”的规则。两项修复前均可复现错误，相关查询改为锁定读后通过。

新增代码的中文注释集中说明状态含义、登录身份与历史归属、数据库加锁顺序、材料上限、文件路径校验及事务回滚清理，便于结合业务流程阅读。
