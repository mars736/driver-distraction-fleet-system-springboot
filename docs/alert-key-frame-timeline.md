# 告警关键帧时间线

已有申诉模块的库在启动前执行 `src/main/resources/db/migrations/20261120_alert_key_frame_timeline.sql`。新库使用完整 `db/schema.sql`。

| 方法和路径 | 结果 |
|---|---|
| GET /api/alerts/{id}/key-frames | 返回 `Result.data` 数组，每项包括 `offset`、`capturedAt` 和 `url`，按 offset 升序。 |
| GET /api/alerts/{id}/key-frames/{offset} | 返回 JPEG。位置为 `-1`、`0` 或 `1`，支持 HEAD。 |
| GET /api/alerts/{id}/key-frame | 原触发帧地址，时间线中的 offset=0 也使用这个地址。 |

时间为北京时间。先按车队、车辆或时间筛选告警，再按告警 ID 读取时间线。管理员可以读取全部告警，司机只能读取本人告警的时间线和图片。找不到告警、越权或所选图片缺失时返回 404。图片请求带 Bearer Token，成功响应不缓存。

行为告警保存触发帧和可用的相邻两帧。取的是已成功处理的识别样本，前后候选各一张，须来自同一摄像头、车辆与司机，时间间隔不超过 30 秒。遇到司机更换、已检测到的处理断档、进程重启或图片缺失时，列表可能只有部分位置。后一帧提交后才会出现在列表，前端可重新查询。旧告警有触发帧时仍可展示；车速未知告警没有关键帧时返回空数组。

为避免连续写盘，服务只暂存每路最近一帧，最多 64 路，每个暂存 JPEG 上限 1 MiB。相邻帧无法写盘时保留已生成的告警，时间线只展示可用图片。事务回滚时清理本次保存的文件。相邻帧缓存在当前进程内，重启后不补写上一进程的未完成时间线。
